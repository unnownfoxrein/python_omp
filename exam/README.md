# Экзамен по ОМП Модуль 2

### Как сдавать решения?

1. Склонировать репозиторий

2. Установить [uv](https://github.com/astral-sh/uv):

```bash
# On macOS and Linux.
curl -LsSf https://astral.sh/uv/install.sh | sh
```

1. Установить Python с помощью uv: `uv python install 3.13.0`

После запуска `uv run python` все зависимости будут установлены все дополнительные зависимости.

4. Сделать ветку `dev`: `git checkout -b dev`. Решать задания нужно будет именно в этой ветке. Для каждой задачи подготовлен соответствующий файлик в папке `solution`.

5. Как только вы готовы отправить решение, то необходимо открыть Pull Request в ветку `main` в вашем репозитории и добавить вашего преподавателя в Reviewers. Важно называть свои Pull Request-ы в формате `Exam. Иванов Иван`. Это помогает преподавателям быстрее ориентироваться среди ваших решений. Pull Request-ы, которые имеют другое название, могут быть проигнорированы.


### Как локально запустить тесты?

1. Для того чтобы запустить тесты на задачу `N` нужно выполнить команду `uv run pytest test/test_taskN.py` из корня репозитория и команду `uv run pytest .`, если вы хотите запустить все тесты. Также вам может помочь флажок `-s`, если вы хотите видеть отладочный вывод в тестах.

2. Также может быть полезно запустить линтеры и форматтер на вашем коде с помощью команды `make fmt lint`.

### Задачи

#### 1. FixedSizeQueue (2 балла)

Данное задание на реализацию структуры данных.

Вам предлагается реализовать очередь на массиве фиксированного размера.

В качестве состояния очереди разрешается использовать только преаллоцированный лист размера `maxlen` и два индекса.

* Очередь не должна оставлять висящие ссылки на объекты, после того как они были вынуты из очереди.
* Очередь должна инициализироваться своим максимальным размером -– `q = FixedSizeQueue(maxlen=10)`.
* Свойство `empty`, возвращающее `True/False`, в зависимости от того, пуста ли очередь. `O(1)`.
* Свойство `full`, возвращающее `True/False`, в зависимости от того, заполнена ли очередь. `O(1)`.
* Метод `len(q)`, возвращающий число элементов в очереди. `O(1)`.
* Метод `q.put(obj)`, добавляющий объект в начало очереди. В случае, если в очереди нет места, необходимо бросить `ValueError`. `O(1)`.
* Метод `q.get()`, достающий объект из конца очереди. В случае, если очередь пуста, необходимо бросить `ValueError`. `O(1)`.
* Оператор `q + obj` должно возвращать новую очередь, никак не связанную с предыдущей, в которую добавлен элемент `obj`. `O(n)`.
* Оператор `q += obj` должно добавлять в текущую очередь элемент `obj`. `O(1)`.
* На очереди должен работать оператор `in`, проверяющий вхождение элемента в очередь. `O(n)`.
* Метод `clone()`, возвращающий независимую копию очереди. `O(n)`.

p.s. `n` -- текущее количество элементов в очереди.

#### 2. trace_if (2 балла)

Напишите декоратор `trace_if`, который будет выводить информацию о вызове функции, только если переданные аргументы удовлетворяют предикату.
```python
>>> @trace_if(lambda x, y, **kwargs: kwargs.get("integral"))
... def div(x, y, *, integral):
... ... return x // y if integral else x / y

>>> div(4, 2, integral=False)
2
>>> div(4, 2, integral=True)
div (4, 2) {'integral': True}
2
```

Для простоты считайте, что мы не рассматриваем функции, которые имеют аргументы по умолчанию.



#### 3. Transaction (2 балла)

Вам необходимо написать менеджер контекста, который позволит безопасно работать с транзакциями.

Напишите класс `Storage`, в котором будут храниться какие-то данные ввиде словаря. Эти данные должны быть закрытыми и
их можно читать только через операцию `[]`. У этого класса должен быть метод `edit`, который возвращает менеджер контекста, позволяющий редактировать
исходный объект (опять же через `[]`). При этом результаты редактирования записываются в исходный объект только если
весь блок выполнился успешно.

Пример использования:
```python
s = Storage()
with s.edit() as se:
    se['a'] = 1
    may_be_an_exception_here()
```

#### 4. FixedSizeQueue Iterator (2 балла)

Расширьте вашу реализацию `FixedSizeQueue` из задачи 1, добавив поддержку итераторов:

1. **Прямой итератор** — метод `__iter__` должен возвращать итератор, который выдает элементы от начала к концу очереди (от первого добавленного к последнему). При этом состояние очереди не должно меняться.

2. **Обратный итератор** — метод `__reversed__` должен возвращать итератор, который выдает элементы в обратном порядке (от последнего добавленного к первому). Для использования напишите `reversed(q)` или `list(reversed(q))`.

**Важно**:
- Создайте отдельный класс `FixedSizeQueueIterator` для реализации итератора
- Итератор должен работать на **копии (snapshot)** данных, сделанной в момент создания итератора
- Итераторы должны корректно работать с **циклическим буфером**: учитывать, что элементы могут "заворачиваться" в конец массива. Например, если в массиве размера 5 индексы `[_, _, 3, 4, 5]` и затем добавили `[6, 7, _, _, _]`, то итератор должен вернуть `[3, 4, 5, 6, 7]` в правильном порядке
- Итерация не должна изменять состояние очереди (не вызывать `get()`)
- Каждый вызов `__iter__` или `__reversed__` создает новый независимый итератор

Пример использования:
```python
q = FixedSizeQueue(maxlen=5)
for i in [1, 2, 3]:
    q.put(i)

# Прямой обход (автоматически вызывает __iter__)
print(list(q))  # [1, 2, 3]

# Обратный обход (автоматически вызывает __reversed__)
print(list(reversed(q)))  # [3, 2, 1]

# Итерация не меняет очередь
print(len(q))  # 3
print(q.get())  # 1

# Пример с циклическим буфером
q2 = FixedSizeQueue(maxlen=5)
for i in range(1, 6):  # Заполняем очередь: [1, 2, 3, 4, 5]
    q2.put(i)
q2.get()  # Извлекаем 1
q2.get()  # Извлекаем 2
q2.put(6)  # Добавляем 6
q2.put(7)  # Добавляем 7
# Теперь в массиве: [6, 7, 3, 4, 5], но логически: [3, 4, 5, 6, 7]
print(list(q2))  # [3, 4, 5, 6, 7] — итератор это учитывает!
```
