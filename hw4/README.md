Обратите внимание на разницу в объёме кода: итератор через `__next__` требует ручного управления стеком (~15 строк), а генератор решает ту же задачу в ~5 строк.

### 2. Планировщик на генераторах (2 балла)

Лёгкими потоками обычно называют конструкции языка, позволяющие писать конкурентные (англ. **concurrent**) приложения, то есть приложения с несколькими контекстами исполнения. Эпитет **лёгкие** подчёркивает, что речь идёт именно об абстракции уровня языка, а не о потоках уровня операционной системы.

В Python кооперативные лёгкие потоки можно реализовать в терминах генераторов. Чтобы понять, как, обратимся к примеру:

```python
def task_foo():
    print("1 task_foo")
    yield pause()
    print("2 task_foo")
    yield pause()

def task_bar():
    for i in range(3):
        print(i + 1, "task_bar")
        yield pause()
```

Мы хотим выполнить их конкурентно:

```python
>>> loop = EventLoop()
>>> loop.add_task(task_foo())
>>> loop.add_task(task_bar())
>>> loop.run()
1 task_foo
1 task_bar
2 task_foo
2 task_bar
3 task_bar
```

Оператор `yield` приостанавливает выполнение текущей задачи и даёт поработать другим.

Будем считать, что задача — это генератор, возвращающий пару `(tag, value)`, где `tag` — строка, описывающая действие планировщика, а `value` — значение для этого действия.

Функция `pause` — сигнал планировщику, что задача ещё не закончила и её нужно вернуть в очередь:

```python
def pause():
    return "pause", None
```

**а (1 балл).** Реализуйте класс `EventLoop`. Конструктор класса должен инициализировать атрибут `tasks` — очередь задач (`collections.deque`). Реализуйте методы:

- `add_task(task)` — добавляет задачу в конец очереди.
- `run()` — запускает задачи в порядке очереди. Для каждой задачи вызывает `next(task)`, обрабатывает результат `(tag, value)`:
  - `"pause"` — вернуть задачу в конец очереди.
  - Неизвестный `tag` — поднять исключение.
  - Если генератор завершился (`StopIteration`), задача удаляется из очереди.

**б (1 балл).** Реализуйте поддержку операции `schedule`. Функция `schedule` принимает задачу и возвращает `("schedule", target)`. При получении `"schedule"` планировщик должен добавить `target` в очередь.

Обратите внимание: если задача, запустившая новую, не завершила исполнение, то она должна находиться в очереди сразу после запущенной задачи.

```python
def schedule(target):
    return "schedule", target
```

Пример:

```python
>>> def countdown(n):
...     if n:
...         print("count", n)
...         yield schedule(countdown(n - 1))
...         print("done ", n)
...
>>> loop = EventLoop()
>>> loop.add_task(countdown(3))
>>> loop.run()
count 3
count 2
done  3
count 1
done  2
done  1
```

Этот планировщик — упрощённая модель того, что делает `asyncio` внутри. Оператор `yield` здесь играет ту же роль, что `await` в `async/await`: приостановить текущую задачу и отдать управление event loop'у.

### 3. Async гонки (3 балла)

**а (1 балл). Параллельный запуск — `asyncio.gather`**

Реализуйте асинхронную функцию:

```python
async def run_concurrently(coros: list) -> list:
```

Функция принимает список корутин, запускает их **все одновременно** с помощью `asyncio.gather` и возвращает список результатов **в том же порядке**, что и входной список.

Пример:

```python
async def slow():
    await asyncio.sleep(0.3)
    return "slow"

async def fast():
    await asyncio.sleep(0.1)
    return "fast"

results = await run_concurrently([slow(), fast()])
# results == ["slow", "fast"]  — порядок сохранён
# Общее время ≈ 0.3с, а не 0.4с
```

**б (1 балл). Гонка — кто первый — `asyncio.create_task`**

Реализуйте асинхронную функцию:

```python
async def first_result(coros: list):
```

Функция запускает все корутины как отдельные задачи (`asyncio.create_task`), возвращает результат той, которая завершилась **первой**, и **отменяет** все остальные.

Используйте `asyncio.wait` с параметром `return_when=asyncio.FIRST_COMPLETED` и метод `task.cancel()`.

Пример:

```python
result = await first_result([slow(), fast()])
# result == "fast"  — slow() была отменена
```

**в (1 балл). Параллельный запуск с таймаутом**

Реализуйте асинхронную функцию:

```python
async def run_with_timeout(coros: list, timeout: float, default=None) -> list:
```

Функция запускает каждую корутину с индивидуальным таймаутом. Если корутина не успевает завершиться за `timeout` секунд, в результат записывается значение `default`. Используйте `asyncio.wait_for` для каждой корутины.

Порядок результатов совпадает с порядком входного списка.

Пример:

```python
results = await run_with_timeout([slow(), fast()], timeout=0.2)
# results == [None, "fast"]
# slow() не успела за 0.2с — вернулось None
```

**Ключевые паттерны:**
- `asyncio.gather(*coros)` — запуск корутин одновременно, результаты в порядке входа
- `asyncio.create_task(coro)` — создание фоновой задачи
- `asyncio.wait(tasks, return_when=FIRST_COMPLETED)` — ожидание первой завершённой
- `task.cancel()` — отмена задачи
- `asyncio.wait_for(coro, timeout)` — запуск с таймаутом

### 4. GETLIST на asyncio (3 балла)

Текстовый протокол GETLIST состоит из трёх операций:

- **LIST** — возвращает список имён доступных файлов, разделённых символами `\r\n`.
- **GET name** — возвращает содержимое текстового файла с именем `name` в кодировке UTF-8.
- **SLOW n** — ждёт `n` секунд и возвращает пустой ответ (имитация медленной операции).

Если запрос клиента не соответствует спецификации, содержит имя несуществующего файла или невалидный аргумент SLOW, сервер должен ответить `ERROR`. Иначе ответ состоит из слова `OK <n>`, за которым следует тело ответа из `n` байтов.

Запросы клиента и ответы сервера всегда заканчиваются символами `\r\n\r\n`.

**а (0.5 балла).** Напишите функцию `virtualize(dir_path)`. Функция принимает путь к директории и возвращает словарь, ключи которого — имена файлов, а значения — содержимое файлов. И ключи, и значения должны быть в байтах (кодировка UTF-8). Используйте `pathlib.Path`.

**б (1.5 балла).** Реализуйте `async def getlist_handler(reader, writer, vfs)` — асинхронный обработчик клиента. Он должен обрабатывать команды `LIST`, `GET` и возвращать `ERROR` для невалидных запросов.

Пример работы:

```python
>>> from functools import partial
>>> vfs = virtualize("/tmp")
>>> handler = partial(getlist_handler, vfs=vfs)
>>> # запускаем сервер
```

```bash
$ nc localhost 8080
LIST

OK 16
bar.txt
foo.txt

GET foo.txt

OK 14
Hello, world!

GET nonexistent

ERROR

INVALID COMMAND

ERROR
```

**в (1 балл). Команда SLOW и конкурентная обработка**

Добавьте поддержку команды `SLOW <n>` в ваш GETLIST-сервер. Команда должна:
- Подождать `n` секунд (используйте `await asyncio.sleep(n)`).
- Вернуть `OK 0\r\n\r\n` после ожидания.

Если `n` не является положительным целым числом, сервер должен вернуть `ERROR\r\n\r\n`.

Ваш сервер должен корректно обрабатывать нескольких клиентов одновременно: пока один клиент выполняет `SLOW 2`, другой клиент должен получать ответы на свои запросы без задержки.

Реализуйте `async def main(host, port, dir_path)`, которая:
- вызывает `virtualize(dir_path)` для подготовки виртуальной ФС;
- запускает сервер через `asyncio.start_server`;
- ожидает `server.serve_forever()`.

Запуск:

```python
if __name__ == "__main__":
    asyncio.run(main("localhost", 8080, "/tmp"))
```

Подсказка: если ваш обработчик корректно использует `await`, несколько клиентов обрабатываются автоматически — event loop переключается между корутинами во время `await asyncio.sleep`.

### 5. Async echo-сервер с улучшениями (3 балла)

Реализуйте асинхронный TCP echo-сервер с тремя улучшениями по сравнению с обычным echo.

**а (1 балл). Counted echo:** Каждое сообщение от клиента возвращается с префиксом — порядковым номером сообщения для данного клиента (начиная с 1). Формат: `N: <сообщение>`. У каждого клиента свой независимый счётчик.

Пример:
```
Client sends:    hello
Server responds: 1: hello
Client sends:    world
Server responds: 2: world
```

```bash
# Терминал 1 (сервер)
$ python solution/task5.py
Echo server started on localhost:8080

# Терминал 2 (клиент)
$ nc localhost 8080
hello
1: hello
world
2: world
```

**б (1 балл). Idle timeout:** Если клиент молчит более `TIMEOUT` секунд (константа в начале файла, по умолчанию 5), сервер отправляет `Timeout: disconnected after N seconds of inactivity\n` и закрывает соединение.

Подсказка: используйте `asyncio.wait_for(reader.read(...), timeout=TIMEOUT)` и обработайте `asyncio.TimeoutError`.

```bash
$ nc localhost 8080
hello
1: hello
# (ждём 5 секунд без ввода)
Timeout: disconnected after 5 seconds of inactivity
```

**в (1 балл). Broadcast:** Если клиент отправляет сообщение, начинающееся с `!broadcast `, сервер должен:
- **Не** отправлять это сообщение обратно отправителю.
- Отправить `<сообщение>\n` **всем остальным** подключённым клиентам.

Для хранения активных соединений используйте глобальное множество `writers: set` (уже определено в файле). При подключении клиента добавляйте его `writer` в множество, при отключении — удаляйте.

Broadcast-сообщения **не** увеличивают счётчик отправителя. Обычные сообщения (без префикса `!broadcast `) продолжают работать как counted echo: `N: <сообщение>`.

Пример с тремя клиентами:

```
Клиент 1:                    Клиент 2:                    Клиент 3:
> hello                      > hi
< 1: hello                   < 1: hi
> !broadcast greetings
                             < greetings                  < greetings
> world
< 2: world
```

Подсказка: при рассылке итерируйте по копии множества (`list(writers)`), пропуская отправителя. Оборачивайте `writer.write` и `writer.drain` в `try/except`, чтобы обрабатывать отключившихся клиентов.

**Ключевые паттерны:**
- `asyncio.wait_for(reader.read(...), timeout=TIMEOUT)` + `except asyncio.TimeoutError`
- Per-client state (счётчик) как локальная переменная в корутине-обработчике
- Глобальное множество `writers` для хранения активных соединений
